# NEXUS Home Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir la Home de NEXUS Training Club como una página comercial, responsive y animada que lleve al visitante a solicitar una clase de prueba.

**Architecture:** `index.html` contendrá bloques semánticos con clases reutilizables. `estilos.css` definirá tokens, componentes y layout mobile-first; `script.js` añadirá interacciones progresivas sin dependencias ni bloquear contenido.

**Tech Stack:** HTML5, CSS3, JavaScript nativo y fotografías remotas de Unsplash.

**Spec:** `docs/superpowers/specs/2026-09-17-nexus-training-club-design.md`

## Global Constraints

- No usar estilos inline ni dependencias externas de JavaScript.
- Diseñar primero para 320–767 px y ampliar solo con `min-width: 768px` y `min-width: 1024px`.
- Usar `#0D0D0D`, `#F2F0EA`, `#C7FF32` y `#727272` como tokens de color.
- Mantener el CTA principal dirigido a `planes.html#clase-prueba`.
- Respetar `prefers-reduced-motion` y evitar desbordamiento horizontal.

### Task 1: Crear el marcado semántico y la conversión de Home

**Files:**

- Modify: `index.html`
- Test: inspección manual en navegador

**Interfaces:**

- Consumes: `estilos.css` y `script.js` desde las etiquetas existentes.
- Produces: secciones `inicio`, `instalaciones`, `modalidades` y `testimonios`; controles `data-menu-toggle`, `data-mobile-menu`, `data-reveal` y `data-count`.

- [ ] **Step 1: Confirmar el estado inicial**

Abrir `index.html` y verificar que el cuerpo no tiene contenido visible.

- [ ] **Step 2: Escribir el contenido de la Home**

Reemplazar el cuerpo por una cabecera accesible con menú móvil, hero, beneficios, instalaciones, modalidades, estadísticas, testimonios, CTA final y footer. Añadir enlaces internos y el CTA a `planes.html#clase-prueba`; usar `alt` descriptivos y `loading="lazy"` fuera del hero.

- [ ] **Step 3: Verificar estructura y rutas**

Run: `rg -n '<main|<header|<footer|<nav|aria-|alt=|planes.html#clase-prueba' index.html`

Expected: landmarks, atributos del menú, texto alternativo y CTAs hacia la prueba.

- [ ] **Step 4: Comprobar anclas en navegador**

Usar la navegación. Expected: los enlaces internos llevan a su sección y el CTA apunta a la futura ruta de planes.

- [ ] **Step 5: Commit**

Run: `git add index.html && git commit -m "feat: build Nexus home structure"`

Expected: un commit con el marcado de Home.

### Task 2: Implementar sistema visual mobile-first

**Files:**

- Modify: `estilos.css`
- Test: inspección responsive manual

**Interfaces:**

- Consumes: clases y atributos de Task 1.
- Produces: tokens y estilos de `.site-header`, `.hero`, `.benefit-list`, `.facility-grid`, `.training-grid`, `.stats-grid`, `.testimonials-grid`, `.final-cta` y `.site-footer`.

- [ ] **Step 1: Definir tokens y componentes base**

Crear `:root` con paleta, espaciado, bordes y timings. Normalizar caja, tipografía, imágenes y enlaces; añadir botones, etiquetas editoriales, contenedor y foco visible.

- [ ] **Step 2: Crear la composición móvil**

Implementar una columna, navegación cerrada, hero alto, CTAs cómodos, grids de una columna y fotografías con `object-fit`. Usar `clamp()` para titulares y `overflow-x: clip` en el documento.

- [ ] **Step 3: Añadir tablet y desktop**

En `min-width: 768px`, crear dos columnas y grids equilibrados. En `min-width: 1024px`, usar navegación horizontal, layout asimétrico de instalaciones y escala editorial mayor.

- [ ] **Step 4: Verificar cinco anchos**

Abrir la Home a 375, 430, 768, 1024 y 1440 px. Expected: no hay scroll horizontal, el menú se colapsa solo en móvil y los CTAs se pueden tocar.

- [ ] **Step 5: Commit**

Run: `git add estilos.css && git commit -m "feat: add Nexus responsive visual system"`

Expected: un commit con el sistema visual responsive.

### Task 3: Añadir interacciones y soporte de movimiento reducido

**Files:**

- Modify: `script.js`
- Modify: `estilos.css`
- Test: inspección manual en navegador

**Interfaces:**

- Consumes: atributos `data-menu-toggle`, `data-mobile-menu`, `data-reveal`, `data-count` y estilos de Tasks 1–2.
- Produces: clases `is-open`, `is-scrolled` e `is-visible` cuando existan los nodos correspondientes.

- [ ] **Step 1: Implementar menú accesible y scroll de cabecera**

Seleccionar controles de forma opcional. Alternar `is-open`, `aria-expanded` y bloqueo de scroll; cerrar con Escape o enlace. Añadir `is-scrolled` al superar el hero.

- [ ] **Step 2: Implementar reveals y contadores**

Usar `IntersectionObserver` cuando exista; revelar una vez los nodos `data-reveal` y animar cada `data-count` con `requestAnimationFrame`. Con movimiento reducido, mostrar el valor final directamente.

- [ ] **Step 3: Añadir transiciones protegidas**

Crear transiciones de reveal, botones, imágenes, tarjetas y menú; incluir `@media (prefers-reduced-motion: reduce)` que reduzca duración y elimine transformaciones decorativas.

- [ ] **Step 4: Verificar flujos críticos**

En móvil y desktop, comprobar menú, Escape, navbar al scroll, reveals y contadores. Expected: sin errores de consola ni reinicios de los contadores.

- [ ] **Step 5: Commit**

Run: `git add script.js estilos.css && git commit -m "feat: add Nexus home interactions"`

Expected: un commit con interacciones de Home.
